# Benchmark: canonicalizer vs. direct questions to Cala

Junction 2026, Cala challenge. Run on 14/11/2026 against the live API. Complements `docs/CALA-CONSISTENCY-REPORT.md` (what the error is and what we know about the graph); this document contains only the benchmark numbers.

## Summary

Five ways of asking Cala the same thing:

| | Direct search | Direct query | MCP agent | MCP agent with Cala's guide | Canonicalizer |
|---|---|---|---|---|---|
| What Cala receives | The question as written, in `POST /v1/knowledge/search` | The question as written, in `POST /v1/knowledge/query` (without a guide or template) | Whatever an agent (Codex) connected to Cala's MCP server decides | The same, with Cala's official guide in the prompt | A query built with a fixed template, in `POST /v1/knowledge/query` |
| Questions | 9 × 3 phrasings = 27 | the same 27 | the same 27 | the same 27 | the same 27 |
| Distinct queries sent to Cala | 27 | 27 | 24 (the agent rewrites the question) | 32 distinct arguments in 35 calls | **9** |
| Questions with the same data across all 3 phrasings | **0 of 9** | **0 of 9** | **1 of 9** | **0 of 9** | **9 of 9** |
| Calls to Cala | 27 | 27 | 25 (2 did not call Cala) | 35 (2 could not connect) | 9 on a cold run (2 in this run; the rest were already cached) |
| Time | 906 s; 33.6 s average (max. 61 s) | 939 s; 34.8 s average (max. 65 s) | 785 s; 29.1 s average (max. 66 s) | 917 s; 34.0 s average (max. 70 s) | ~21 s in this run (almost all cached) |

Sending natural language without canonicalization is inconsistent across both knowledge APIs and through MCP, which is how most agents will use Cala, **even with Cala's official guide loaded**. The data, companies, and even the response format change depending on how the question is phrased.

## What was measured

- **9 questions** across 7 types: a specific round, founders, acquisitions, total funding, investors, executives, and 3 lists filtered by country, sector, and amount.
- **3 phrasings per question**: Spanish with accents, Spanish without accents or with word order changed, and English.
- **Direct search**: the text as written sent to `knowledge/search`.
- **Direct query**: the text as written sent to `knowledge/query`, which according to Cala's documentation accepts natural language as well as its query language.
- **MCP agent**: Codex CLI (`gpt-6-luna`, low effort) connected to Cala's MCP server (`https://api.cala.ai/mcp/`) as its only tool, without Cala's guide. It receives the question as written and chooses which tools to call. It is asked to answer in English and list names and figures separately, to compare data rather than languages. Script: `canonizador/bench_mcp.py`; results: `canonizador/bench/results_mcp.json`.
- **MCP agent with Cala's guide**: the same agent and prompt, with Cala's official usage guide (`docs/internal/CALA-SKILL.md`, copied from `github.com/cala-ai/cala-skill`) added at the beginning. No canonicalizer. `python3 bench_mcp.py --guia`; results: `canonizador/bench/results_mcp_guia.json`.
- **Canonicalizer**: `canonizador.api.answer()`, which reduces the question to an intent and builds the `knowledge_query` query with a fixed template.
- Everything ran sequentially, with caching and resumability. Raw results are in `canonizador/bench/results.json`.

What the agent did:

- **It always used natural-language search.** All 25 calls were to `knowledge_search`; it never used `knowledge_query` or the entity endpoints, which are what Cala recommends for specific data.
- **It rewrote the question before sending it.** In 16 of the 25 calls, it did not pass the text as written: it translated it into English, paraphrased it, or added requests ("and how much did each invest?"). Even questions already in English reached Cala with different wording. The 25 calls used 24 distinct texts, so nearly every version became a new query for Cala.
- **It did not call Cala for 2 of the 27 questions.** For one, it answered "no hay herramientas de Cala disponibles en esta sesión"; the MCP connection failed in that run. For the other (Glovo founders, without accents), it answered without consulting anything, despite being asked to use Cala only: it presented a memory-based answer as if it came from Cala.

## MCP agent with Cala's guide

The official guide tells the agent which tool to use in each case (structured queries for filters, entities for specific data, natural-language search only for open-ended questions) and to stop if a call fails instead of making things up.

| Question | Tools used across the 3 phrasings | Result |
|---|---|---|
| Amenitiz Series B | search · search · search | Same data (€38.9M, Kfund via Leadwind); the wording changes |
| Glovo founders | entities · search · none | 3 founders · 2 · no answer (MCP unavailable) |
| Mews acquisitions | entities + search · search · search | Different lists |
| Factorial total funding | entities + search in all 3 | **€523M · €523M · $572M (and $420M)** |
| Wolt investors | search in all 3 | Different lists |
| TravelPerk executives | search · search · none | Avi Meir · Avi Meir · no answer (MCP unavailable) |
| Hotel technology in Spain, > 10M | structured query in all 3 | Amenitiz in all 3, with different figures (€76–81M · ~€77M · ~€70M); the other companies vary (Lodgify, The Hotels Network, Perk, BEONx, Civitatis) |
| Fintech in Finland, > 5M | structured query in all 3 | Different lists and figures |
| Climate tech in Germany, > 20M | structured query in all 3 | Different lists and figures |

Compared with the agent without the guide:

- **The guide changes the tools, not consistency.** Without the guide, all 25 calls were natural-language searches. With the guide, it used structured queries for all 9 list questions and entities for 3 questions, but none of the 9 questions returned the same data across all 3 phrasings (without the guide, 1 of 9 did).
- **The agent still writes the query in its own way.** With structured queries, each phrasing produced a different query, and Cala returned different companies and figures. This is the same as what we measured when translating freely with the guide (`docs/CALA-CONSISTENCY-REPORT.md`, section 2.3): the guide teaches the query language but does not define a canonical form.
- **With the guide, it does not make things up when a call fails.** In the first run, 6 of 27 questions could not connect to MCP, and for all of them the agent said the tools were unavailable, as the guide instructs. On retrying those 6, 4 worked and 2 still could not connect; the table shows the repeated run. Without the guide, in one case it answered from memory.
- **MCP connections fail frequently**: 8 of 33 attempts in total across both runs with the guide. We do not know whether this is Cala's usage limit or an MCP server problem.

## Examples of actual differences without canonicalization

This is not just wording or language: the data changes.

| Question | Direct search (3 phrasings) | Direct query (3 phrasings) | Canonicalizer |
|---|---|---|---|
| Factorial total funding | $420M and €523M · €523M and $570M · $572M | $420M · $572M / €523M · €523M (~$570M+) | $572M |
| Glovo founders | 3 founders · 3 · 2 (without Gerard Olivé) | 2 · 3 (including Gerard Olivé) · 2 | 2 (Oscar Pierre, Sacha Michaud) |
| Hotel technology in Spain, > 10M | highlights TravelPerk · no highlighted companies · highlights Amenitiz | TravelPerk, Civitatis, Amenitiz… · TravelPerk, Amenitiz… · TravelPerk, Amenitiz… | Amenitiz and Room00, every time |
| Climate tech in Germany, > 20M | highlights Enpal in two, none in the third | starts with 1KOMMA5° and Flix · starts with Enpal · starts with Enpal | Enpal, 1KOMMA5°, Sunfire…, every time |

For direct search, figures and names were extracted automatically from the beginning of each answer (amounts and bold text), so they show what the response foregrounds.

**Direct query also changes the row format.** For the same question, fields are called `company`, `name`, `empresa`, `investor`, or `startup`, and the round lead is `lead_investor` or `leader`. Rows may be in Spanish or English depending on the question. A program consuming these rows cannot depend on field names. For Amenitiz's Series B, the data matches (€38.9M, Kfund), although all three rows have different formats.

## How to read these numbers (limitations)

- **Facts in common.** Direct search shares 0 facts across phrasings for all 9 questions, but according to `CALA-CONSISTENCY-REPORT.md`, `context` IDs are generated per response. Therefore, that 0 does not prove anything by itself and we do not use it as a metric. We use the returned entity IDs (which are stable) and the response data.
- **Different answers.** In both direct modes, the text and format also change with the language. That is why the examples table compares figures and names, not the text.
- **Calls.** In this run, the canonicalizer made only 2 calls because the other queries were already cached from earlier tests. On a cold run there would be 9: one per question instead of one per phrasing.
- **Consistency is not accuracy.** The canonicalizer guarantees the same answer for the same intent, not that it is correct. Two cases to examine:
  - Glovo: the canonicalized result returns 2 founders; several direct answers name a third (Gerard Olivé). We did not verify which data is correct.
  - Amenitiz: cross-checking against the entity endpoints shows a discrepancy: the round is listed as 3,000 M EUR in the structured data and as €38.9 M in the query. The canonicalizer flags it instead of silently choosing one.
- **MCP agent.** This is one agent (Codex with a small model and low effort), with and without Cala's guide. A larger model might choose better tools, but the underlying problem (each phrasing produces a different query) does not depend on the tool chosen. The "same names" comparison uses the list the agent itself extracted from its answer.
- **Small sample.** 9 questions, 3 phrasings each, one run per mode. The sector depends on a closed list of labels, and a sector outside the list falls into "other".

## How to reproduce

```bash
cd canonizador
uv sync --extra dev
uv run python bench.py          # resumable; writes bench/results.json
python3 bench_mcp.py            # MCP agent; resumable; writes bench/results_mcp.json
python3 bench_mcp.py --guia     # same with Cala's guide; writes bench/results_mcp_guia.json
```
Requires `CALA_API_KEY` in `backend/.env` and the Codex CLI logged in (the LLM that extracts the intent). Questions are in `bench/questions.json`. For a cold run, delete `canonizador/cache/` and `bench/results.json`.
